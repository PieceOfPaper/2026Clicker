# 큰 숫자 표기 규칙

이 문서는 `2026Clicker`에서 `BigNumber` 값을 플레이어에게 표시할 때 사용하는 단위 선택, 정밀도, 문자 단위 자동 생성 및 경계 처리 규칙을 정의합니다.

숫자의 저장·연산 책임은 `BigNumber`가 담당하고, 이 문서의 규칙은 별도의 숫자 포맷터가 담당하는 것을 원칙으로 합니다.

## 1. 확정된 기본 정책

| 항목 | 규칙 |
| --- | --- |
| 단위 승격 정책 | 2to4 |
| UI 소수부 | 소수점 아래 1자리 고정 |
| 고정 단위 | `K`, `M`, `B`, `T` |
| 자동 문자 단위 시작 | `aa` |
| 문자 단위 확장 | 소문자 → 첫 글자만 대문자 → 전체 대문자 → 글자 길이 증가 |
| 단위 간격 | 1,000배, 즉 10진 지수 3 증가 |
| 후행 0 | 항상 유지 |
| 천 단위 구분자 | 사용하지 않음 |
| 소수점 기호 | 현재는 문화권과 관계없이 `.` 사용 |
| 음수 | 절댓값으로 단위를 결정하고 표시 결과 앞에 `-` 유지 |
| 0 | `0.0`으로 표시 |

### 기본 예시

| 실제 값 | UI 표시 |
| ---: | --- |
| 0 | `0.0` |
| 123 | `123.0` |
| 9,999 | `9999.0` |
| 10,000 | `10.0K` |
| 123,456 | `123.5K` |
| 1,000,000 | `1000.0K` |
| 3,123,456 | `3123.5K` |
| 9,999,999 | `9999.9K` |
| 10,000,000 | `10.0M` |
| -3,123,456 | `-3123.5K` |

## 2. 2to4 단위 정책

2to4는 단위를 10,000배마다 변경하는 체계가 아닙니다. 단위 자체는 `K → M → B → T`처럼 1,000배마다 존재하지만, 다음 단위로 변환했을 때 정수부가 한 자리라면 이전 단위를 유지합니다.

단위가 붙은 계수는 원칙적으로 다음 범위를 사용합니다.

```text
10.0 이상 10000.0 미만
```

따라서 `3,123,456`은 `3.1M`이 아니라 `3123.5K`로 표시하고, 값이 `10,000,000`에 도달했을 때 `10.0M`으로 승격합니다.

### 1to3과 비교

| 실제 값 | 일반적인 1to3 | 2026Clicker 2to4 |
| ---: | --- | --- |
| 1,000 | `1.0K` | `1000.0` |
| 10,000 | `10.0K` | `10.0K` |
| 1,000,000 | `1.0M` | `1000.0K` |
| 3,123,456 | `3.1M` | `3123.5K` |
| 10,000,000 | `10.0M` | `10.0M` |
| 1,000,000,000 | `1.0B` | `1000.0M` |
| 10,000,000,000 | `10.0B` | `10.0B` |

### 채택 이유

- `3.1M`처럼 다음 단위의 한 자리 숫자로 바뀌며 수치가 작아 보이는 현상을 줄입니다.
- `3123.5K`처럼 이전 단위에서 수치가 계속 커지는 모습을 보여 성장 체감을 강화합니다.
- 보유 재화와 가격이 가까운 범위에 있을 때 같은 단위로 표시될 가능성이 높아 비교하기 쉽습니다.
- 정수부가 최대 네 자리이므로 소수부는 한 자리만 표시해 전체 문자열 길이를 제한합니다.

## 3. 단위 인덱스와 고정 단위

단위 인덱스는 10진 지수가 3 증가할 때마다 1 증가합니다.

| 단위 인덱스 | 단위 | 단위 기준값 |
| ---: | --- | ---: |
| 0 | 없음 | 10^0 |
| 1 | K | 10^3 |
| 2 | M | 10^6 |
| 3 | B | 10^9 |
| 4 | T | 10^12 |
| 5 | aa | 10^15 |
| 6 | ab | 10^18 |
| 7 | ac | 10^21 |

단위의 기준값과 실제 UI에서 해당 단위를 처음 사용하는 값은 다릅니다. 2to4 정책에서는 단위 기준값의 10배가 되어야 새 단위를 사용합니다.

```text
aa의 기준값: 10^15
aa 표시 시작: 10^16

10^15 → 1000.0T
10^16 → 10.0aa
```

0이 아닌 값의 절댓값에 대한 10진 지수를 `exponent`라고 할 때 기본 단위 인덱스는 다음 규칙으로 결정합니다.

```csharp
unitIndex = exponent < 4
    ? 0
    : (exponent - 1) / 3;
```

| 10진 지수 | 단위 인덱스 | 선택 단위 |
| ---: | ---: | --- |
| 0~3 | 0 | 없음 |
| 4~6 | 1 | K |
| 7~9 | 2 | M |
| 10~12 | 3 | B |
| 13~15 | 4 | T |
| 16~18 | 5 | aa |

## 4. 문자 단위 자동 생성

`K`, `M`, `B`, `T` 이후의 단위는 코드에 전체 목록을 저장하지 않고 영문 알파벳 26자를 이용해 자동 생성합니다.

각 글자는 0부터 25까지의 숫자에 대응합니다.

```text
0 = a 또는 A
1 = b 또는 B
...
25 = z 또는 Z
```

### 4.1 두 글자 소문자

```text
aa, ab, ac ... ax, ay, az
ba, bb, bc ... bx, by, bz
...
za, zb, zc ... zx, zy, zz
```

- 개수: 26² = 676개
- `aa`: 단위 인덱스 5, 기준값 10^15
- `zz`: 단위 인덱스 680, 기준값 10^2040

### 4.2 두 글자 첫 글자 대문자

소문자 두 글자를 모두 사용하면 첫 글자만 대문자인 블록으로 이동합니다.

```text
Aa, Ab, Ac ... Ax, Ay, Az
Ba, Bb, Bc ... Bx, By, Bz
...
Za, Zb, Zc ... Zx, Zy, Zz
```

- 개수: 26² = 676개
- `Aa`: 단위 인덱스 681, 기준값 10^2043
- `Zz`: 단위 인덱스 1356, 기준값 10^4068

### 4.3 두 글자 전체 대문자

첫 글자만 대문자인 블록을 모두 사용하면 전체 대문자 블록으로 이동합니다.

```text
AA, AB, AC ... AX, AY, AZ
BA, BB, BC ... BX, BY, BZ
...
ZA, ZB, ZC ... ZX, ZY, ZZ
```

- 개수: 26² = 676개
- `AA`: 단위 인덱스 1357, 기준값 10^4071
- `ZZ`: 단위 인덱스 2032, 기준값 10^6096

### 4.4 ZZ 이후의 무제한 확장

`BigNumber`의 범위에 제한을 두지 않기 위해 `ZZ` 이후에는 글자 길이를 하나 늘리고 같은 대소문자 단계를 반복합니다.

```text
ZZ
→ aaa, aab ... zzz
→ Aaa, Aab ... Zzz
→ AAA, AAB ... ZZZ
→ aaaa, aaab ...
```

일반 규칙은 다음과 같습니다.

1. 현재 글자 길이의 전체 소문자 조합을 생성합니다.
2. 현재 글자 길이의 첫 글자만 대문자인 조합을 생성합니다.
3. 현재 글자 길이의 전체 대문자 조합을 생성합니다.
4. 세 블록을 모두 사용하면 글자 길이를 1 증가시키고 1번부터 반복합니다.

| 글자 길이 | 전체 소문자 | 첫 글자 대문자 | 전체 대문자 |
| ---: | --- | --- | --- |
| 2 | `aa...zz` | `Aa...Zz` | `AA...ZZ` |
| 3 | `aaa...zzz` | `Aaa...Zzz` | `AAA...ZZZ` |
| 4 | `aaaa...zzzz` | `Aaaa...Zzzz` | `AAAA...ZZZZ` |

문자 단위는 대소문자를 구분합니다. 예를 들어 `aa`, `Aa`, `AA`는 서로 다른 단위입니다.

## 5. 자동 생성 알고리즘 요구사항

문자 단위 생성기는 다음 입력과 출력을 가져야 합니다.

```text
입력: K를 1로 보는 단위 인덱스
출력: K, M, B, T 또는 자동 생성된 문자 단위 문자열
```

문자 단위 구간에서는 다음 절차를 사용합니다.

1. 단위 인덱스에서 고정 단위 네 개와 문자 단위 시작 오프셋을 제외합니다.
2. 글자 길이를 2로 시작합니다.
3. 현재 길이의 블록 크기 `26^length`를 계산합니다.
4. 전체 소문자, 첫 글자 대문자, 전체 대문자 블록 중 어느 블록인지 결정합니다.
5. 블록 내부 인덱스를 고정 길이 26진수로 변환합니다.
6. 해당 블록의 대소문자 규칙을 적용합니다.
7. 세 블록을 초과하면 `3 × 26^length`를 빼고 글자 길이를 증가시켜 반복합니다.

`BigNumber`가 무제한 범위를 목표로 하므로 단위 인덱스와 `26^length` 계산도 `int` 또는 `long`의 최대값에 의존하지 않아야 합니다.

## 6. 소수점과 반올림

모든 UI 표시는 소수점 아래 한 자리를 고정으로 보여줍니다.

```text
10     → 10.0
10K    → 10.0K
123.45K → 123.5K
1000K  → 1000.0K
```

후행 0을 제거하지 않습니다.

```text
10K  (사용하지 않음)
10.0K (사용)
```

표시를 위해 숫자를 축소한 다음 소수 둘째 자리에서 반올림합니다. 반올림 결과가 `10000.0` 이상이 되면 다음 단위로 승격한 뒤 다시 포맷합니다.

```text
9,999,950
→ 9999.95K
→ 10000.0K
→ 10.0M
```

중간 결과인 `10000.0K`를 최종 UI에 노출해서는 안 됩니다.

정확히 중간값인 경우의 반올림 방식과 보유 재화·구매 비용에 서로 다른 반올림 방향을 적용할지는 경제 시스템 구현 전에 별도로 결정합니다.

## 7. 포맷 처리 순서

1. 0인지 확인하고 0이면 `0.0`을 반환합니다.
2. 부호를 분리하고 절댓값을 사용합니다.
3. 절댓값의 10진 지수로 2to4 단위 인덱스를 계산합니다.
4. 선택한 단위의 기준값으로 원본 값을 나누어 표시 계수를 구합니다.
5. 계수를 소수점 한 자리로 반올림합니다.
6. 반올림된 계수가 `10000.0` 이상이면 단위 인덱스를 1 증가시키고 다시 계산합니다.
7. 단위 인덱스를 고정 단위 또는 자동 문자 단위로 변환합니다.
8. `F1`에 해당하는 한 자리 고정 형식으로 계수를 출력합니다.
9. 부호, 계수, 단위를 결합합니다.

## 8. 구현 구조 원칙

숫자 연산과 UI 표현을 분리합니다.

```text
BigNumber
├─ 값 저장
├─ 사칙연산
├─ 비교
└─ 직렬화

BigNumberFormatter
├─ 2to4 단위 선택
├─ 소수점 한 자리 포맷
├─ 단위 경계 재정규화
└─ 문자 단위 자동 생성
```

`BigNumber.ToString()`에 게임 전용 규칙을 직접 고정하지 않고, 명시적인 포맷터 또는 포맷 옵션을 통해 호출하는 방향을 우선합니다.

## 9. 테스트 경계값

최소한 다음 값의 직전·정확한 값·직후를 테스트해야 합니다.

| 경계 | 테스트 목적 |
| --- | --- |
| 0 | 0 전용 처리 |
| 9,999 / 10,000 | 단위 없음에서 K로 전환 |
| 9,999,999 / 10,000,000 | K에서 M으로 전환 |
| 9,999,999,999 / 10,000,000,000 | M에서 B로 전환 |
| 10^15 / 10^16 | T 유지 후 aa 전환 |
| `zz` 마지막 범위 / `Aa` 시작 범위 | 소문자에서 첫 글자 대문자로 전환 |
| `Zz` 마지막 범위 / `AA` 시작 범위 | 첫 글자 대문자에서 전체 대문자로 전환 |
| `ZZ` 마지막 범위 / `aaa` 시작 범위 | 두 글자에서 세 글자로 전환 |
| 양수/음수 동일 절댓값 | 부호와 단위 선택 일관성 |
| 반올림 전 9999.94 / 9999.95 계수 | 반올림에 의한 단위 승격 |

## 11. 미결정 사항

- 정확한 중간값 반올림 방식: ToEven 또는 AwayFromZero
- 보유 재화는 내림, 구매 비용은 올림으로 표시할지 여부
- 문화권별 소수점·천 단위 구분자 현지화 여부
- 디버그 화면에서 전체 숫자 또는 과학적 표기를 함께 제공할지 여부
